## 배경

AD3 플랫폼에서 전산생물학자와 의약화학자는 일상적으로 3D 단백질 구조와 2D 화학 다이어그램을 검사합니다. 두 가지 특수 라이브러리가 이 작업을 처리합니다:

- **Molstar** — RCSB Protein Data Bank에서도 사용하는 오픈소스 3D 고분자 뷰어
- **RDKit.js** — 업계 표준 RDKit 화학정보학 툴킷의 WebAssembly 포트

두 라이브러리 모두 크기가 상당하며(각각 수 MB), 최적화되지 않은 AD3 코드베이스에서는 3D나 화학 구조를 전혀 표시하지 않는 페이지를 포함한 모든 라우트에 eager 번들링되어 있었습니다.

## 문제

프로덕션에서 Molstar와 RDKit은 **3D도 분자 다이어그램도 렌더링하지 않는 라우트에서 메인 번들 무게의 50% 이상을 차지**했습니다. 표준 접근법인 라우트 스코프 `dynamic()` 임포트로 깔끔하게 해결할 수 있었지만, 어떤 라우트가 어떤 라이브러리가 필요한지 정확히 파악하는 것이 선행되어야 했습니다.

### 2. 라우트 스코프 동적 임포트

두 라이브러리 모두 최상위 임포트에서 라우트 스코프 `dynamic()` 호출로 마이그레이션했습니다:

```tsx
// Before: 모든 라우트가 비용 부담
import { MolstarViewer } from '@molstar/viewer'

// After: 3D를 렌더링하는 라우트만 Molstar 로드
const MolstarViewer = dynamic(() => import('@/components/3d/MolstarViewer'))

// RDKit.js는 화합물 관련 라우트에서만 로드
const RdkitDepiction = dynamic(() => import('@/components/chem/RdkitDepiction'))
```

### 3. 로딩 UX

각 무거운 컴포넌트는 최종 치수에 맞는 스켈레톤 플레이스홀더를 받아, 지연 로드 중 레이아웃 시프트(CLS)를 방지합니다.

## 실제 데모: 이 사이트에 적용된 동일한 기법

아래 패널은 두 라이브러리가 온디맨드로 로드되는 것을 보여줍니다. DevTools → Network를 열고 "rdkit"으로 필터링하면 이 페이지에서만 라이브러리가 로드되는 것을 확인할 수 있습니다.

<MolecularViewer />

Molstar 뷰어는 iframe을 통해 임베드됩니다(JS 번들과 독립적으로 로드됨). RDKit.js(~2.5 MB WASM)는 이 컴포넌트가 렌더링될 때만 CDN에서 로드됩니다.

## 주요 결정

**왜 npm 임포트 대신 iframe을 사용했나요?** Molstar의 전체 npm 패키지(`molstar`)는 브라우저 전용 케이스 스터디 사이트에 적합하지 않은 서버사이드 의존성(Express, compression)을 끌어옵니다. iframe은 molstar.org에서 호스팅되는 공식 Molstar 뷰어로 렌더링을 위임합니다.

**왜 번들링 대신 CDN에서 RDKit.js를 로드하나요?** RDKit.js는 임포트 방식과 관계없이 런타임에 가져오고 컴파일되어야 하는 WebAssembly 바이너리입니다. CDN 스크립트 태그를 통한 로딩이 가장 투명한 접근법이며, DevTools에서 라우트 스코프 로딩을 쉽게 확인할 수 있습니다.
