## Context

In the AD3 platform, computational biologists and medicinal chemists routinely inspect 3D protein structures and 2D chemical diagrams. Two specialized libraries handle these tasks:

- **Molstar** — An open-source 3D macromolecular viewer used by the RCSB Protein Data Bank itself
- **RDKit.js** — A WebAssembly port of the industry-standard RDKit cheminformatics toolkit

Both are large (several MB each) and, in the unoptimized AD3 codebase, were bundled eagerly on every route — even pages that never showed 3D or chemical structures.

## Problem

In production, Molstar plus RDKit contributed more than **50% of the main bundle weight** on routes that neither rendered 3D nor displayed molecular diagrams. The standard approach — route-scoped `dynamic()` imports — could solve this cleanly, but required precise knowledge of which routes needed which libraries.

### 2. Route-scoped dynamic imports

Both libraries were migrated from top-level imports to route-scoped `dynamic()` calls:

```tsx
// Before: every route paid the cost
import { MolstarViewer } from '@molstar/viewer'

// After: only routes that render 3D load Molstar
const MolstarViewer = dynamic(() => import('@/components/3d/MolstarViewer'))

// RDKit.js loaded only on compound-related routes
const RdkitDepiction = dynamic(() => import('@/components/chem/RdkitDepiction'))
```

### 3. Loading UX

Each heavy component receives a skeleton placeholder that matches its final dimensions, preventing layout shift (CLS) during lazy load.

The Molstar viewer is embedded via iframe (it loads independently of the JS bundle). RDKit.js (~2.5 MB WASM) loads from CDN only when this component renders.

## Key decisions

**Why iframe for Molstar instead of npm import?** The full Molstar npm package (`molstar`) pulls in server-side dependencies (Express, compression) that are inappropriate for a browser-only case study site. The iframe delegates rendering to the official Molstar viewer hosted at molstar.org.

**Why CDN for RDKit.js instead of bundling?** RDKit.js is a WebAssembly binary that must be fetched and compiled at runtime regardless of how it's imported. Loading via CDN script tag is the most transparent approach and makes it easy to verify route-scoped loading in DevTools.
