## 배경

Next14-R3F 포트폴리오 프로젝트(별도 케이스 스터디 참조)에는 프로덕션 등급 배포 파이프라인이 필요했습니다. 일반적인 "SSH 접속, 풀, 빌드, 재시작" 주기 대신, 완전한 GitOps 파이프라인을 구축했습니다:

```
개발자 푸시 → GitHub → Jenkins 빌드 & 푸시 → GitOps 저장소 업데이트 → ArgoCD 동기화 → K3s 클러스터
```

**GitHub:** [Lajancia/Next14-R3F](https://github.com/Lajancia/Next14-R3F) (Jenkinsfile 포함)

## 파이프라인 아키텍처

### GitHub → Jenkins 트리거

GitHub에 구성된 웹훅이 푸시 이벤트를 Jenkins 서버로 전송합니다. `main` 브랜치에 푸시가 발생하면 파이프라인이 자동으로 시작됩니다.

### Stage 1: 체크아웃

Jenkins가 푸시된 커밋에서 저장소를 체크아웃하여, 빌드가 개발자가 의도한 것과 정확히 일치하도록 합니다.

### Stage 2: Docker 빌드 & 푸시

```groovy
stage('Docker Build & Push') {
    steps {
        script {
            def shortCommit = sh(returnStdout: true,
              script: 'git rev-parse --short HEAD').trim()
            sh "docker build -f dockerfile -t ${GHCR_IMAGE}:${shortCommit} ."
            sh "docker tag ${GHCR_IMAGE}:${shortCommit} ${GHCR_IMAGE}:latest"
            sh "docker push ${GHCR_IMAGE}:${shortCommit}"
            sh "docker push ${GHCR_IMAGE}:latest"
        }
    }
}
```

멀티-스테이지 Docker 빌드는 의존성 관리에 pnpm을 사용합니다:

```dockerfile
FROM node:20-alpine AS base
RUN corepack enable && corepack prepare pnpm@9.11.0 --activate

FROM base AS deps
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --no-frozen-lockfile

FROM base AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN pnpm panda && pnpm build

FROM base AS runner
WORKDIR /app
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public
```

주요 최적화:
- **pnpm** — 더 빠른 설치와 npm 대비 디스크 효율성
- **`output: 'standalone'`** — 최소 Docker 이미지 (~110 MB runner 스테이지)
- **멀티-스테이지 빌드** — deps 캐시 레이어가 코드 변경 시 재설치 방지

### Stage 3: GitOps 저장소 업데이트

서버에 SSH로 접속하는 대신, Jenkins가 별도의 **GitOps 저장소**를 업데이트합니다:

```groovy
stage('Update GitOps Repo') {
    steps {
        script {
            def shortCommit = sh(...)
            sh """
                git clone https://github.com/g3941813-svg/next-r3f-ops.git
                sed -i 's|image: ...|image: ${GHCR_IMAGE}:${shortCommit}|' next-r3f.yaml
                git commit -m "chore: update image tag to ${shortCommit}"
                git push
            """
        }
    }
}
```

GitOps 저장소에는 ArgoCD가 감시하는 단일 Kubernetes 매니페스트(`next-r3f.yaml`)가 포함되어 있습니다.

### Stage 4: ArgoCD 동기화

K3s 클러스터에서 실행되는 ArgoCD는 3분마다 GitOps 저장소를 폴링합니다. 이미지 태그 변경을 감지하면 새로운 매니페스트를 클러스터에 자동 동기화합니다 — 제로 다운타임 롤링 업데이트.

## 인프라 다이어그램

포트폴리오 사이트의 Pipeline 페이지는 이 아키텍처를 인터랙티브 타임라인으로 시각화합니다:

```
사용자 → Nginx (프록시 + SSL) → Next.js (R3F 포트폴리오) → Jenkins (CI 파이프라인)
                                                                   ↓
                                                             GHCR (이미지 레지스트리)
                                                                   ↓
                                                             GitOps 저장소 (매니페스트)
                                                                   ↓
                                                             ArgoCD (자동 동기화)
                                                                   ↓
                                                             K3s 클러스터 (프로덕션)
                                                                   ↓
                                                             Tailscale (보안 VPN 접속)
```

각 노드는 역할에 대한 상세 설명과 함께 클릭 가능합니다.

## 인프라 상세

### K3s 클러스터

- 단일 VPS 배포에 이상적인 경량 Kubernetes 배포판
- Nginx 리버스 프록시 뒤의 VPS에서 실행
- 보안 관리 접근을 위해 Tailscale VPN을 통해 서비스 노출

### Nginx

- SSL 종단(Let's Encrypt) 처리하는 리버스 프록시
- K3s에서 실행되는 Next.js 애플리케이션으로 트래픽 라우팅
- 성능을 위한 정적 자산 캐싱 헤더 구성

### Tailscale

- WireGuard 기반 메시 VPN으로 보안 클러스터 접근
- K3s 노드에 열린 포트 없음 — 모든 트래픽이 Tailscale을 통해
- 관리 대시보드 및 모니터링은 VPN을 통해서만 접근 가능
