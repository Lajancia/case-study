## Context

A personal portfolio site that doubles as a technical showcase. Instead of a conventional static portfolio, I built an immersive 3D experience with React Three Fiber (R3F) — combining 3D graphics, internationalization, build-time styling, and automated deployment in a single Next.js 14 project.

Everything described below is verifiable in the public repository:

**GitHub:** [Lajancia/Next14-R3F](https://github.com/Lajancia/Next14-R3F)

A representative scene component — the pattern is a self-contained R3F component per scene:

```tsx
import { Canvas } from '@react-three/fiber'
import { OrbitControls, Environment, useGLTF } from '@react-three/drei'

function KeyboardScene() {
  const { nodes, materials } = useGLTF('/keyboard.glb')
  return (
    <group>
      {Object.values(nodes).map((node, i) => (
        <mesh key={i} geometry={node.geometry} material={materials[node.name]} />
      ))}
    </group>
  )
}
```

State for cross-canvas interaction is handled with **zustand** and **valtio** (shared scene state), with `tunnel-rat` passing DOM ↔ canvas props and `suspend-react` coordinating async asset loading.

### 2. Bilingual support (i18next, ko/en)

Full Korean and English localization — verifiable in `src/app/i18n/locales/{ko,en}/`:

- **Route-based language URLs**: `/ko/...` and `/en/...` via the `[lng]` dynamic segment, prerendered per language with `generateStaticParams`
- **Detection order**: path → html tag → cookie → navigator, using i18next's `LanguageDetector` + `resourcesToBackend` for per-namespace lazy loading
- **Namespaced translation files** per section (menu, gallery, infrastructure, …)

### 3. Build-time styling (Panda CSS)

Styling uses **Panda CSS** (`panda.config.mjs`, `panda` / `panda:dev` build scripts):

- Zero-runtime CSS generation at build time — no style injection cost at runtime
- Type-safe design tokens and recipes shared across components
- Responsive variants without media-query boilerplate

### 4. Infrastructure diagram page

A dedicated section renders the full deployment topology — user → Nginx → Next.js → Jenkins → K3s → GitHub → Tailscale — as an animated diagram with signal packets flowing between nodes (`src/parts/infrastructure/InfrastructureDiagram.tsx`).

## Key decisions

**Why Panda CSS alongside Tailwind?** The project started with Tailwind and migrated the design system to Panda CSS for its typed tokens and build-time output. Both configs remain in the repo, reflecting the incremental migration rather than a big-bang rewrite.

**Why route-based i18n instead of a cookie-only switch?** Language in the URL keeps each locale linkable and shareable, and lets `generateStaticParams` prerender both languages as static pages — no runtime locale negotiation on the server.

**Why separate CI/CD case study?** This project originally contained both the 3D portfolio and the Jenkins/K3s pipeline. They are documented separately because each addresses a different engineering concern — visualization and infrastructure.

## Deployment (summary)

The repo ships the full deployment tooling — `Jenkinsfile`, multi-stage `dockerfile`, `docker-compose.yml`, and PM2 `ecosystem.config.js`. Jenkins builds the image with a git short-SHA tag, pushes it to GHCR (`latest` + SHA), and updates the GitOps repo. The complete pipeline — including the K3s/ArgoCD side — is documented in the dedicated case study below.
